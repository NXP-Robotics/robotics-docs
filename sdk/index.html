Robotics SDK¶

robotics-sdk is a glue layer that unifies multiple robotics platforms across all of the supported software stacks (e.g. PX4, Zephyr, AM32, etc…). This project owns no firmware source on its own; instead it pins the exact upstream revisions (via west manifests), dispatches builds to the right build system, and provides a way to download pre-built artifacts.

Requirements¶

The SDK builds inside a Docker container, so the host only needs Docker and a few basic tools. The host must provide:

  • Docker (see the installation instructions below).

  • git, to clone this repository.

  • Around 10 GB of free disk space for the Docker image, plus additional space for the checked-out sources and build outputs.

  • Network access to github.com, from which the Dockerfile downloads the Zephyr SDKs while building the image. If you are behind a firewall, make sure you pass the proper proxy host and port to the Docker commands as shown below.

Prerequisites and configuration¶

Host operating system¶

The Docker-based build flow is validated on Ubuntu 24.04 LTS. Use Ubuntu 24.04 as the host OS; older releases (e.g. Ubuntu 22.04) are not currently supported and may fail while building the Docker image.

Corporate network: proxy and CA certificates¶

If you build from a corporate network you will typically need both a proxy and the corporate CA certificate so that TLS connections (to github.com, package indexes, etc.) succeed inside the Docker build.

  • Proxy. The docker build / docker run examples below accept http_proxy / https_proxy values. These are placeholders of the form http://<proxy>:<port> — replace <proxy> and <port> with the values that apply to your own machine and site. Do not copy the examples verbatim; there is no single proxy that works for everyone. If your host does not need a proxy, omit these arguments entirely.

  • CA certificate. If your organization performs TLS inspection, downloads inside the image build can fail with certificate-verification errors. Make the corporate root CA available during the build, for example by copying the .crt into the build context and installing it in the image (/usr/local/share/ca-certificates/ + update-ca-certificates), or by configuring the CA on the host Docker daemon. Consult your local IT documentation for the exact certificate file and installation method.

Quick getting started guide¶

Given the number of software stacks supported by the SDK, managing all of their package dependencies on your build machine can become tedious. Because of this, robotics-sdk provides a Dockerfile, which can be used to build a Docker image with all of the package dependencies included in it.

To get started, please make sure Docker is installed on your machine. For an Ubuntu-based machine, you can follow these instructions. To check if everything went smoothly with the installation, you can try to run the hello-world Docker image:

sudo docker run hello-world

Apart from Docker, a few system packages are required. These can be installed by running:

sudo apt-get update
sudo apt-get install -y git

To prepare the development environment, first clone the robotics-sdk repository by running:

mkdir -p ~/robotics-workdir && cd ~/robotics-workdir

git clone -b <branch> https://github.com/nxp-robotics/robotics-sdk.git

📝 Note: branch is the name of the branch or tag you want to use. We recommend always choosing a release branch/tag. For the ROBOTICS_0.7.0 release, the name of the branch would be robotics-0.7.0.

For example, to clone the robotics-0.7.0 branch:

mkdir -p ~/robotics-workdir && cd ~/robotics-workdir

git clone -b robotics-0.7.0 https://github.com/nxp-robotics/nxp-robotics-sdk.git

You can also pass a tag to the -b option to check out a specific release. For example, to check out the <tag> tag:

mkdir -p ~/robotics-workdir && cd ~/robotics-workdir

git clone -b <tag> https://github.com/nxp-robotics/robotics-sdk.git

📝 Note: Release tags are listed on the repository’s releases/tags page; use the tag that matches the release you want.

Command reference guide¶

robotics-sdk uses west to manage all of its components (e.g. building firmware images, downloading pre-built binaries, updating git revisions, etc…). The documentation found below provides an overview of what you can achieve using west and robotics-sdk.

📝 Note: For all commands requiring a platform name as argument (e.g. west sdk build -p <platform>), you’ll have to use one of the supported platform names listed by running west sdk list.

📝 Note: For all build or download commands, all of the binaries will be available under ~/robotics-workdir/bin.

  1. Displaying help information

The --help option can be used to display additional information regarding a command or a sub-command (e.g. documentation, supported options, etc…). This option should be used as the “ultimate” source of truth since it should always be up to date.

Examples of how this option could be used:

# print help information about the sdk command
west sdk --help

# print help information about the build sub-command
west sdk build --help

  1. List available platforms

To list all of the available platforms:

west sdk list

# prints additional information such as supported stacks, shields and examples
west sdk list -v

  1. Download pre-built binaries

To download the pre-built binaries:

west sdk download -p <platform>

For example, to download the pre-built binaries for the MR-NAVQ95 platform:

west sdk download -p navq95

  1. Build binaries from source

To build all of the available binaries from source for a given platform:

west sdk build -p <platform>

For example, to build all of the available binaries for the MR-NAVQ95 platform:

west sdk build -p navq95

The aformentioned command builds all of the available binaries for the target platform (i.e. all stacks, all examples, etc…). You can choose to build a specific stack by using the --stack option:

west sdk build -p <platform> --stack <stack>

For example, to build the PX4 stack for the MR-NAVQ95 platform:

west sdk build -p navq95 --stack px4

Warnings and environment-specific notes¶

The warnings below only apply in specific situations (corporate networks, WSL2, tag checkouts). They are collected here so that the step-by-step flow above stays easy to follow — consult the relevant one only if it applies to your setup.

Warning: hello-world on a corporate network¶

On a corporate network, docker run hello-world pulls the image from Docker Hub and will fail unless Docker can reach the registry through your proxy. Configure the Docker daemon proxy (see the Docker documentation) before running the validation step.

Warning: detached HEAD after a tag checkout¶

Doing a checkout on a tag will put your repository in a detached HEAD state. You can run git switch -c <branch> to create a branch.

Warning: docker build proxy on a corporate network¶

If you’re sitting behind a corporate firewall, you may also need to specify the proxies to the build command. You can do so by using the --build-arg option. Replace <proxy> and <port> with your own site’s values (see Corporate network):

sudo docker build --build-arg UID=$(id -u) \
		  --build-arg GID=$(id -g) \
		  --build-arg http_proxy=http://<proxy>:<port> \
		  --build-arg https_proxy=http://<proxy>:<port> \
		  -t robotics-sdk -f robotics-sdk/Dockerfile .

Warning: WSL2 DNS resolution during docker build¶

When building on WSL2, the Docker container may lose DNS resolution for external hosts (e.g. github.com), causing the Zephyr SDK download to fail with Temporary failure in name resolution. Add --network=host to the build command so the container shares the WSL2 network stack directly (see Troubleshooting):

sudo docker build --network=host \
		  --build-arg UID=$(id -u) \
		  --build-arg GID=$(id -g) \
		  -t robotics-sdk -f robotics-sdk/Dockerfile .

Warning: docker run proxy on a corporate network¶

If you’re sitting behind a corporate firewall, you may also need to pass the proxy-related environment variables to the run command. You can do so by using the -e option (again, substitute your own <proxy>/<port>):

sudo docker run -it -v ~/robotics-workdir:/home/robotics \
		-e http_proxy=http://<proxy>:<port> \
		-e https_proxy=http://<proxy>:<port> \
		robotics-sdk

Troubleshooting / FAQ¶

Docker build fails downloading the Zephyr SDK on WSL2 (Temporary failure in name resolution / unable to resolve host address 'github.com'). On WSL2, Docker containers run inside an extra virtualization layer (Hyper-V), whose isolated virtual network can lose DNS resolution for external hosts. Add --network=host to the docker build command so the container shares the WSL2 network stack directly (see the WSL2 warning under Quick getting started guide).

docker run hello-world hangs or fails on the corporate network. Docker cannot reach Docker Hub without a proxy. Configure the Docker daemon proxy per the Docker documentation, then retry.

TLS / certificate-verification errors during docker build. Your network performs TLS inspection and the corporate CA is not trusted inside the image. Install the corporate CA certificate as described in Corporate network.

The proxy example commands don’t work for me. The http://<proxy>:<port> values are placeholders — substitute the proxy host and port for your own site. If you don’t need a proxy at all, drop the --build-arg http_proxy=... / -e http_proxy=... arguments.
