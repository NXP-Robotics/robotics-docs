MR-NavQ95 DTB Overlays in U-Boot¶

The MR-NavQ95 board uses a single base device tree blob (imx95-navq.dtb) combined with per-connector .dtbo overlay files that are applied at boot time by U-Boot. This design lets you swap cameras, displays, or Ethernet adapters on the board’s B2B connectors without rebuilding the kernel.

Overview¶

At boot, U-Boot:

  1. Loads the base DTB from the boot medium into memory at fdt_addr_r.

  2. Resizes the in-memory DTB to leave room for overlay data.

  3. Iterates over the three connector overlay variables (csi_b2b, dsicsi_b2b, eth_b2b).

  4. For each variable that is not none and not empty, loads the named .dtbo file into ov_addr_r and calls fdt apply to merge the overlay into the in-memory DTB.

  5. Boots the kernel with the fully patched device tree.

Environment Variables¶

The relevant variables are defined in board/nxp/imx95_evk/imx95_evk.env under the CONFIG_TARGET_IMX95_NAVQ guard.

Overlay selection variables¶

Variable

Default value

Connector / function

csi_b2b

imx95-navq-csi-imx219.dtbo

Port A — CSI-only (camera)

dsicsi_b2b

imx95-navq-dsicsi-imx219.dtbo

Port B — DSI/CSI combo

eth_b2b

imx95-navq-sja1110a.dtbo

Ethernet B2B (SJA1110A switch)

Set any variable to none (or leave it empty) to skip that overlay entirely.

Helper commands¶

Command

What it does

apply_one

Loads ${ovfile} using ${get_cmd}, then calls fdt apply

apply_overlays

Sets the FDT address, resizes the blob, then runs apply_one for each active connector variable

boot_os

Runs apply_overlays, then boots the kernel with booti

modules_help

Prints the list of available .dtbo files for each connector

How apply_overlays Works¶

apply_overlays=
    fdt addr ${fdt_addr_r};
    fdt resize 0x20000;
    echo "NavQ-B connectors: csi_b2b=${csi_b2b} dsicsi_b2b=${dsicsi_b2b}";
    if test "${csi_b2b}" != none; then if test "${csi_b2b}" != ""; then
        setenv ovfile ${csi_b2b}; run apply_one; fi; fi;
    if test "${dsicsi_b2b}" != none; then if test "${dsicsi_b2b}" != ""; then
        setenv ovfile ${dsicsi_b2b}; run apply_one; fi; fi;
    if test "${eth_b2b}" != none; then if test "${eth_b2b}" != ""; then
        setenv ovfile ${eth_b2b}; run apply_one; fi; fi;

For each connector, apply_one does:

apply_one=
    echo "  overlay: ${ovfile}";
    if ${get_cmd} ${ov_addr_r} ${ovfile}; then
        if fdt apply ${ov_addr_r}; then true;
        else echo "  WARN: failed to apply ${ovfile}"; fi;
    else echo "  WARN: ${ovfile} not found on boot partition"; fi;

  • ${get_cmd} is set by the active boot path (mmcboot sets it to fatload mmc ${mmcdev}:${mmcpart}, while netboot sets it to dhcp or tftp). This ensures overlay loading works for both MMC and network boot.

  • fdt apply merges the overlay blob at ov_addr_r into the base DTB already set active via fdt addr. Phandle fixups are performed automatically by U-Boot’s fdt_overlay_apply_verbose() (see boot/fdt_support.c).

Overlay application sequence¶

mmcboot
  |-- fatload mmc  ->  loadaddr  (kernel Image)
  |-- fatload mmc  ->  fdt_addr_r  (imx95-navq.dtb)
  `-- boot_os
        |-- apply_overlays
        |     |-- fdt addr ${fdt_addr_r}
        |     |-- fdt resize 0x20000
        |     |-- apply_one  (csi_b2b overlay)
        |     |     |-- fatload mmc -> ov_addr_r  (.dtbo)
        |     |     `-- fdt apply ${ov_addr_r}
        |     |-- apply_one  (dsicsi_b2b overlay)
        |     `-- apply_one  (eth_b2b overlay)
        `-- booti ${loadaddr} - ${fdt_addr_r}

Selecting a Different Module¶

From the U-Boot prompt, run run modules_help to see all available overlays:

=> run modules_help
NavQ-B module selection (one .dtbo per connector):
  csi_b2b    (port A, CSI-only): imx95-navq-csi-{imx219,imx477}.dtbo | none
  dsicsi_b2b (port B, DSI/CSI): imx95-navq-dsicsi-{imx219,imx477,disp-7inch,disp-5inch,lt8912b}.dtbo | none
  current: csi_b2b=imx95-navq-csi-imx219.dtbo dsicsi_b2b=imx95-navq-dsicsi-imx219.dtbo
  example: setenv dsicsi_b2b imx95-navq-dsicsi-disp-7inch.dtbo; saveenv

To permanently switch, for example, port B to an imx477 camera:

=> setenv dsicsi_b2b imx95-navq-dsicsi-imx477.dtbo
=> saveenv
=> reset

To disable a connector overlay (e.g. no camera on port A):

=> setenv csi_b2b none
=> saveenv
=> reset

Adding a New Overlay¶

  1. Create the DTS overlay source (.dtso) for your hardware and build it to produce a .dtbo binary.

  2. Copy the .dtbo file to the FAT boot partition of the eMMC or SD card (the same partition that holds Image and imx95-navq.dtb).

  3. At the U-Boot prompt, point the appropriate connector variable to your new file:

    => setenv csi_b2b imx95-navq-csi-mymodule.dtbo
=> saveenv

  4. Reboot — apply_overlays will load and apply your overlay automatically.
